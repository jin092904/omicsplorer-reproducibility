# OmicsPlorer 복합 질의 사람 평가 워크북 v1

## 이 평가가 필요한 이유

검색창이 긴 자연어 문장을 받아들인다는 사실만으로는 복잡한 질의를 잘 처리한다고 말할 수 없다. 질병, 조직, 생물종, 분석법, 비교군과 제외 조건이 함께 들어간 질의에서 실제 상위 결과가 그 조건을 얼마나 충족하는지 사람이 판정해야 한다.

이 워크북은 다음 주장을 정량적으로 검토하기 위한 준비물이다.

> OmicsPlorer는 여러 연구 조건을 포함한 자연어 질의를 실행할 수 있으며, 지원 저장소의 후보를 통합해 관련 데이터셋을 찾도록 돕는다.

비교 결과가 나오기 전에는 `더 정확하다`, `기존 검색보다 우수하다` 또는 `복잡한 의도를 이해한다`고 쓰지 않는다. 결과와 신뢰구간을 확인한 뒤 관측된 범위만 원고에 반영한다.

## 파일 역할

| 파일 | 누가 언제 작성하는가 | 역할 |
|---|---|---|
| `01-query-authoring-sheet.csv` | 검색 결과를 보기 전에 질의 작성자가 작성 | 사람이 실제로 검색하고 싶은 질문 60개를 고정 |
| `02-expected-criteria-sheet.csv` | 같은 시점에 AI가 초안을 만들고 질의 작성자가 검토·확정 | 각 질문에서 반드시 만족해야 할 조건과 제외 조건을 고정 |
| `03-result-judgment-template.csv` | 검색·블라인드 풀 생성 후 판정자가 작성 | 시스템과 원래 순위를 숨긴 후보 데이터셋의 관련성을 판정 |
| `validate_workbook.py` | 작성 중과 최종 고정 직전에 실행 | 행 수, 질의 ID, 필수 조건 수와 누락을 검사 |
| `05-query-and-criteria-review-ko.md` | 질의 작성자가 02 시트를 확정하기 전에 사용 | 한국어 질의와 필수·제외 조건을 한 화면에서 대조·검토 |

CSV는 LibreOffice Calc, Excel 또는 VS Code에서 열 수 있다. 쉼표가 들어간 문장은 셀 안에서 입력하면 프로그램이 자동으로 따옴표를 처리한다. 여러 기대값은 쉼표 대신 `|`로 구분한다.

## 왜 60개인가

기존 외부 비교 사전등록안은 새 confirmatory 질의를 최소 60개로 정했다.

- `simple` 20개: 명시적인 비교·제외 설계 없이 한 연구 주제를 묻는 질의
- `medium` 20개: 질병·조직·분석법 등 확인할 조건 3개 이상을 결합한 질의
- `complex` 20개: 비교군, 반복 시점, 짝지은 표본 또는 제외 조건과 여러 생물학적 조건을 함께 요구하는 질의

이 수가 작은 차이를 반드시 검출한다고 보장하지는 않는다. 질의별 결과와 bootstrap 95% 신뢰구간을 함께 보고한다. 60개를 채우기 어렵다면 일부만 먼저 작성해 수집 절차를 시험할 수 있지만, 그 질의는 pilot으로 표시하고 최종 confirmatory 집합에 다시 사용하지 않는다.

## 사용자가 지금 해야 할 일

### 1. 질문 작성

`01-query-authoring-sheet.csv`에서 각 행의 빈칸을 채운다.

- 먼저 `query_en` 또는 `query_ko` 중 본인이 가장 자연스럽게 작성할 수 있는 언어로 질문을 쓴다.
- 대응 언어 문장도 같은 연구 의도가 되도록 작성하거나 검토한다.
- 키워드 나열보다 실제 연구자가 사용할 법한 질문을 쓴다.
- 특정 검색 서비스의 결과나 검색 문법을 보면서 질문을 고치지 않는다.
- `results_not_seen_yes`에는 결과를 보지 않고 작성했다면 `yes`를 쓴다.
- AI가 번역이나 문장 교정을 도왔다면 `notes`에 범위를 기록하고, 최종 연구 의도는 사람이 확인한다.

`domain_slot`과 `category_slot`은 질의 다양성을 위한 자리다. 정확히 그 질병을 강제하는 값은 아니지만, 가능한 한 해당 분야와 설계에 맞춘다.

### 2. 기대 조건 작성

검색하기 전에 `02-expected-criteria-sheet.csv`를 채운다. 정답 accession을 억지로 찾을 필요는 없다. 복합 질의에는 정답이 여러 개이거나 완전한 정답이 없을 수 있기 때문이다.

다음 중 질문에서 실제로 요구하는 조건만 적는다.

- 질병 또는 상태
- 조직
- 세포 유형
- 생물종
- 분석법 또는 omics modality
- 연구 설계
- 비교군
- 시점·치료·용량
- 반드시 없어야 하는 조건

`known_relevant_gse`는 이미 알고 있는 확실한 GEO Series가 있을 때만 `GSE12345|GSE67890`처럼 적는다. 해당 accession이 조건을 만족한다는 근거 URL도 함께 적는다. 모르면 비워 두는 것이 임의의 정답을 만드는 것보다 낫다.

필요한 조건 수는 다음과 같다.

- simple: 2개 이상
- medium: 3개 이상
- complex: 5개 이상

`why_this_query_is_realistic`에는 그 질문이 실제 연구 상황에서 나올 만한 이유를 한 문장으로 적는다.

02 시트의 60행은 질의 문장만 바탕으로 AI 보조 초안을 작성했으며, 검색 결과의 제목, accession과 순위는 조건 작성에 사용하지 않았다. 이호진은 2026-09-02에 한글 통합 검토표로 60개 질의와 조건을 모두 확인하고 내용이 맞음을 승인했다. 이에 `criteria_author`를 `Hojin Lee (reviewed AI-assisted draft)`로 기록했으며, 사람 검토가 완료된 현재 상태에서만 `--final` 검사가 통과한다.

### 3. 결과를 보기 전에 고정

두 시트를 완성한 뒤 다음 검사를 실행한다.

```bash
cd protocols/complex-query-evaluation-v1
python3 validate_workbook.py --final
```

검사가 통과하면 두 CSV의 Git commit과 SHA-256을 고정한다. 그 뒤에야 OmicsPlorer, NCBI GEO DataSets와 OmicsDI 수집을 시작한다. 결과를 본 뒤 질문이나 기대 조건을 바꾸면 confirmatory 평가가 아니라 exploratory 변경으로 별도 기록한다.

## 검색과 비교 방법

주 비교는 세 서비스가 공통으로 취급할 수 있는 GEO Series로 제한한다.

- OmicsPlorer: GEO source로 제한
- NCBI GEO DataSets: `gse[Entry Type]`만 adapter가 추가
- OmicsDI: GEO repository 제한만 adapter가 추가
- 세 서비스에 동일한 영어 free-text를 전달
- 서비스별로 유리하도록 질의를 수동 변환하지 않음
- 각 서비스 상위 10개를 합치고 같은 GSE는 하나로 합침

OmicsPlorer가 추가로 연결하는 SRA/ENA와 GDC 범위는 별도의 coverage 결과로 설명하고, 공통 GEO ranking 점수와 섞지 않는다. 한국어 질의는 외부 서비스와 억지로 비교하지 않고 OmicsPlorer의 다국어 보조 트랙으로 분석한다.

## 사람 판정 방법

수집 후 기존 pooling 코드가 `03-result-judgment-template.csv` 형식의 실제 후보 시트를 만든다. 이때 판정자에게 다음 정보는 숨긴다.

- 어느 시스템이 반환했는지
- 원래 순위와 시스템 점수
- 한 후보가 몇 시스템에 나타났는지

판정자는 제목, 설명, 생물종, 분석법과 원문 링크를 보고 `relevance_0_3`을 매긴다.

- `3`: 질문의 핵심 조건과 연구 설계를 모두 명확히 만족
- `2`: 주요 조건 대부분을 만족해 실제 검토 후보로 유용
- `1`: 주제 일부만 관련되고 핵심 조건 또는 설계가 부족
- `0`: 무관하거나 명시한 제외 조건을 위반

각 조건 칸에는 `1`(충족), `0`(불충족), `NA`(그 질문에서 요구하지 않음)를 쓴다. 근거가 부족해 판정할 수 없으면 무리하게 1을 주지 말고 `0`으로 처리한 이유를 `notes`에 적거나, 분석 전에 별도의 `uncertain` 규칙을 확정한다.

두 명이 독립 판정하는 것이 권장된다. 저자 두 명이 판정하면 `두 저자에 의한 blinded 판정`이라고 쓰며 외부 독립 평가라고 부르지 않는다. 한 명만 판정하면 inter-rater agreement를 계산하지 않고 single-annotator 한계를 밝힌다.

## 보고할 정량 지표

### 주 지표

- 사람의 0–3 관련성 판정을 이용한 `nDCG@10`
- OmicsPlorer–NCBI와 OmicsPlorer–OmicsDI의 질의별 paired difference
- 10,000회 query-level bootstrap 95% 신뢰구간

### 보조 지표

- `Precision@10`, `MRR@10`, `Success@10`, `bpref`
- 상위 10개 안에 모든 필수 조건을 만족하는 데이터셋이 하나 이상 있는 비율
- 결과별 필수 조건 충족률
- simple, medium, complex 층별 결과
- 제외 조건 위반률
- 알려진 GSE가 있을 때 Hit@1/5/10과 reciprocal rank
- 실패·timeout 비율과 실제 브라우저 기준 latency 분포

복잡한 층에서 OmicsPlorer의 결과가 좋더라도 단순 층까지 포함한 전체 결과, 차이의 신뢰구간과 실패율을 함께 제시한다. 유리한 질의만 골라 본문에 넣지 않는다.

## 현재 원고와의 관계

이 워크북은 기존의 392개 내부 회귀 관찰을 대체하지 않는다. 기존 평가는 네 검색 mode가 동결된 설정에서 계획대로 실행됐는지를 보여준다. 이번 사람 평가는 반환 결과가 실제 연구 질문에 얼마나 관련되는지를 추가로 본다.

평가가 완료되면 다음과 같이 원고를 보강할 수 있다.

1. 방법에 사람 작성 질의, 공통 GEO corpus, 블라인드 pooling과 판정 규칙 추가
2. 결과에 nDCG@10과 모든 조건 만족 Success@10 및 신뢰구간 추가
3. Figure 3을 내부 facet 집계와 사람 관련성 평가의 두 패널로 갱신하거나 사람 평가를 새 주 패널로 교체
4. 보충자료에 질의, 기대 조건, qrels, 질의별 결과와 분석 코드를 공개

관측 결과가 우월성을 지지하지 않더라도 숨기지 않는다. 그 경우 OmicsPlorer가 지원하는 복합 질의 유형과 실제 강점·약점을 정직하게 설명하는 근거로 사용한다.
